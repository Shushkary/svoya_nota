# «Своя нота» · интегрированное мобильное приложение · архитектура v1

Новое приложение доступно по `/svoya-nota-app/` (API: `/svoya-nota-app-api/`).
Существующее приложение `https://torion.su/svoya-nota/` не изменяется.

## Идея продукта

Пять частей одной практики — **Питание, Мышление, Чувства, Воля** и **Аккорд**
(согласованность) — собраны в одну недельную петлю. Очередность практик в течение недели построена по алгоритму
постепенного восстановления регуляции нервной системы (развитие тонуса
блуждающего нерва): от тела и дыхания — к ощущениям, голосу, ясной мысли,
действию и тёплому контакту, с днём интеграции в конце.

Язык приложения — современный, спокойный, светский. Без упоминания
духовных и религиозных традиций.

## Недельный алгоритм (домен `week.py` / `weekPlan.js`)

| День | Тема | Модуль-акцент | Физиологическое основание |
|---|---|---|---|
| 1 | Дыхание и опора | дыхание | медленное дыхание ~5.5–6/мин, удлинённый выдох — дыхательная аритмия (RSA) |
| 2 | Тело и ощущения | чувства·тело | интероцепция, мягкие температурные стимулы |
| 3 | Голос и резонанс | дыхание·голос | гудение и звучание на выдохе — вибрационная стимуляция гортани |
| 4 | Ясная мысль | мышление | устойчивое внимание в спокойном состоянии |
| 5 | Действие и воля | воля | посильное действие через сопротивление в безопасном окне |
| 6 | Связь и тепло | чувства | доброжелательный контакт, сострадательное отношение к себе |
| 7 | Интеграция | обзор | недельная петля адаптации, отдых, прогулка |

Питание — сквозная ежедневная составляющая (ритм приёмов, КБЖУ).

**Аккорд** — отдельная вкладка согласованности. Смысл практик опирается на
современные исследования работы мозга и влияния убеждений и среды на
поведение; имена авторов и теоретические термины в интерфейс не выносятся:

- «Переждать волну» — эмоция как телесная волна: опора, назвать ощущение,
  не продолжать внутреннюю историю, спокойный выдох, оценка через 60–90 секунд
  (без утверждения, что любая эмоция заканчивается ровно за 90 секунд);
- «Кто сейчас говорит?» — четыре внутренних голоса (ясный разбор · осторожность
  и порядок · живой отклик · широкий взгляд), ведущий и подавленные голоса;
- «Четыре голоса — один аккорд» — каждый голос отвечает на один вопрос,
  затем формируется объединённое решение;
- «Старая нота — новая нота» — автоматическое убеждение заменяется не
  аффирмацией, а честной проверяемой формулировкой + малый эксперимент;
- «Фильтр ноцебо» — поиск катастрофических формулировок («всегда», «никогда»,
  «всё пропало») и их точная честная переформулировка;
- «Среда сильнее намерения» — менять сигналы среды, а не требовать силы воли:
  что убрать, что сделать заметнее, как сократить действие до двух минут.

Цикл вкладки: Заметь → Различи → Услышь → Выбери → Сделай → Проверь.

Правила антихрупкости планировщика:

- каждый день самодостаточен: пропуск не ломает неделю и не «обнуляет серию»;
- главная метрика возвращения — время между отклонением и возвращением;
- при низкой утренней отметке состояния планировщик предлагает «мягкий день»
  (дыхание вместо запланированной практики), не считая это отклонением;
- неделя привязана к календарю (Пн–Вс), а не к «идеальной серии».

## Петля (принцип продукта)

```
отметка состояния (до) → практика дня → отметка (после) → рефлексия
        ↑                                                    ↓
недельный обзор ← агрегация ← журнал (питание · активность · циклы воли)
```

Все данные пользователя собираются ради этой петли и видны ему в «Динамике».

## Тороид (главная визуализация «Динамики»)

SVG-тороид вокруг силуэта человека. Отображение данных:

- **четыре дуги потока** по вертикали тела: живот — Питание, грудь — Чувства,
  голова — Мышление, внешний контур — Воля; полнота дуги = активность модуля за 7 дней;
- **ядро (ось) тороида** — Аккорд: яркость оси = практики согласованности
  и сам-оценка «в своей ноте» за неделю;
- **плотность линий** = регулярность (доля дней с любой практикой);
- **тепло цвета** = среднее самочувствие (сам-отчёты 1–5);
- **скорость потока** (анимация) = энергия: шаги и сон из трекера;
- история — мини-тороиды прошлых недель + спарклайны.

Тороид — иллюстрация и метафора, не измерение здоровья; подпись это оговаривает.

## Чистая архитектура

Frontend (`src/`):

```
ui (App, tabs, Toroid, components)  →  domain (weekPlan, loop, kbju, practices)
                                    →  infrastructure (api, storage, image)
```

domain не импортирует React/DOM/fetch; infrastructure не импортирует ui.
Имена localStorage-ключей — в `domain/keys.js` (единственный источник истины;
iframe-виджеты дублируют их литералами, т.к. являются standalone HTML).

Backend (`server/nota/`):

```
presentation (FastAPI DTO) → application (use cases, ports) → domain (чистые правила)
                                        ↑
adapters (SQLite-репозиторий, LLM-шлюз aitunnel/yandex) ← composition.py (env)
```

- Хранилище — SQLite (stdlib `sqlite3`): нет новых процессов на ВМ с 1 ГБ RAM;
  репозиторий за портом — замена на PostgreSQL не трогает домен.
- LLM — порт `ModelGateway`; адаптеры: `aitunnel` (OpenAI-совместимый,
  `https://api.aitunnel.ru/v1`) сейчас, `yandex` (Yandex AI Studio) — переключение
  через env без изменения кода, `disabled` — предсказуемый 403 (fail closed).
- КБЖУ по фото (`POST /api/meals/analyze`) и по тексту (`POST /api/meals/estimate`):
  strict JSON, фото не сохраняется, лимиты размера, ручной ввод — всегда доступный fallback.

## Офлайн-first и синхронизация

Приложение полностью работает без сервера: журнал в localStorage,
расчёты петли и тороида — локальные (`domain/loop.js`). Сервер — резервная
копия и ИИ-прокси. Синхронизация — идемпотентный batch-upsert по `client_id`
(outbox; при конфликте побеждает последняя запись — правка на устройстве
перезаписывает серверную копию). Восстановление на новом устройстве —
`GET /api/snapshot` по токену (вкладка «Ещё»): серверные записи подмешиваются
к локальным, локальные не затираются.

Новая регистрация, синхронизация и snapshot требуют отдельного versioned
согласия на серверную обработку; факт согласия хранится в `data_consents`.
Локальный режим не требует согласия и остаётся полностью рабочим. Технические
меры не заменяют организационные обязанности оператора — контрольный список:
[`docs/russian-legal-checklist.md`](russian-legal-checklist.md).

## Трекеры активности

Порт «активность за день»: шаги, сон (ч), пульс покоя, HRV (опционально).
Источники: ручной быстрый ввод; импорт CSV (выгрузки Health Connect / Zepp /
Huawei Health / Garmin); всё опционально — без трекера петля работает.

## Данные (сущности журнала)

- `state` — отметка состояния: at, updatedAt, phase (morning/evening/pre/post), calm, energy, clarity, warmth (1–5), note
- `practice` — сессия практики: at, module, practiceId, plannedDay, durationSec, completed, preId/postId, reflection
- `meal` — приём пищи: at, description, kcal/protein/fat/carb, source (manual/text_ai/photo_ai), confidence
- `will` — волевой цикл: intention, minStep, plannedAt, status (planned/started/done/cancelled/missed), startedAt, finishedAt, resistance, reflection
- `activity` — день активности: date, steps, sleepHours, restingHr, hrv, source

Все записи имеют устройство-генерируемый `client_id`; мутации идемпотентны.

## Развёртывание (ВМ SpaceWeb, не трогая /svoya-nota/)

- статика → `/var/www/torion-shop/svoya-nota-app/` (Vite base `/svoya-nota-app/`);
- API → `/opt/nota`, venv, systemd `nota-api.service`, uvicorn `127.0.0.1:8090`;
- БД → `/var/lib/nota/nota.db` (владелец сервисного пользователя);
- nginx: `location /svoya-nota-app/` (статика) и `location /svoya-nota-app-api/` → 8090, security-заголовки;
- env `/etc/nota/api.env` (root-only): `NOTA_LLM_API_KEY`, лимиты, провайдер.

Перед обновлением и по расписанию создаётся консистентная копия БД (не обычным
копированием WAL-файла):

```sh
cd /opt/nota
NOTA_DB_PATH=/var/lib/nota/nota.db venv/bin/python scripts/backup_sqlite.py \
  --destination /var/backups/nota
```

Скрипт использует SQLite Backup API, выполняет `quick_check` копии и публикует
её атомарно. Резервные копии должны храниться вне диска приложения и иметь
проверяемую политику удержания.
